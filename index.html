How do you investigate Logs in Production? (Log Analysis Masterclass)
💬 0s Hook: "In production support, log analysis is my primary diagnostic tool. I use a structured 3-phase investigation workflow..."
  • Real-Time Triage: Running 'tail -f' to observe live events and 'grep -i -C 5 "Exception"' to isolate root cause stack traces.
  • Log Classification: Inspecting HTTP access codes in /var logs (4xx client errors vs 5xx server errors), GC logs, and Autosys out/spool logs.
  • Safe Log Maintenance: Safely zeroing active logs using 'cat /dev/null > log_file' without breaking file handles held by running processes.
📋 Deep Investigation Steps & Commands
• Production Log Analysis Workflow: 1. Live Tracking: tail -100f /var/log/application/catalina.out | grep -E "ERROR|FATAL|Exception" 2. Contextual Searching: grep -i -C 5 "NullPointerException" server.log (Pulls 5 lines before & after the crash). 3. Compressed/Rotated Logs: zgrep -i "Connection timeout" app_log-2026-*.gz (Searches gzip files without extracting). 4. HTTP Log Codes: Reviewing access logs: 400-499 indicate user/client permission errors, while 500-599 signify backend server, thread, or database connectivity drops. 5. Autosys Job Logs: Inspecting /autosys/spool or log output to diagnose missing dependencies, input data corruptions, and permission failures.
